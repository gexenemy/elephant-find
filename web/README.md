# Finder — веб-сцена (React Three Fiber)

Минимальное приложение, которое загружает сцену из Blender и проверяет, что она дошла до Three.js без потерь.

## Запуск

Нужен Node.js 18+.

```
cd Documents\FinderGame\web
npm install
npm run dev
```

Откройте адрес, который покажет Vite (обычно http://localhost:5173).

- `http://localhost:5173/?debug` — панель проверки: группы иерархии, 11 слонов, камера, число draw calls
  и проверка, кликается ли каждый слон по центру. Клавиша **R** накладывает рендер Blender поверх сцены.
- Параметры света в адресе: `?light=1&fill=1&ambient=1&exposure=1&shadows=0&tm=agx` (их можно сочетать с `?debug`).
  `tm` — тональная компрессия: `agx` (как в Blender, по умолчанию), `neutral`, `aces`, `none`.
- Свечение (bloom): `?bloom=0` выключает; `bloomI` — сила (0.8), `bloomR` — радиус ореола (0.4; больше — дымка на весь кадр),
  `bloomT` — порог (1.0: светятся только материалы с emission сильнее 1 — гирлянда, огонь, свечи, фонари).
  При включённом свечении тональная компрессия идёт последним эффектом, после bloom.

## Откуда берётся сцена

GLB читается прямо из `..\export\finder_room.glb` (это `publicDir` в `vite.config.js`), копировать его не нужно.
Чтобы обновить сцену: в Blender на вкладке Scripting откройте текст `fg_export.py`, нажмите **Run Script**
и перезагрузите страницу.

## Что важно знать про перенос из Blender

- **Камера.** glTF не хранит сдвиг объектива (shift) и привязку сенсора, поэтому они переданы в
  `CAM_Main.userData`, а `src/blenderCamera.js` восстанавливает их через `camera.setViewOffset`.
  Без этого вся сцена уезжает на 14 % высоты вниз.
- **Кадр.** Сцена показывается в рамке 3:2 (как рендер в Blender), чтобы композиция не менялась на разных экранах.
- **Слоны.** У каждого `userData.game_role === 'hidden_target'`, `target_id`, `found`. Объект с несколькими
  материалами приходит как Group из нескольких Mesh, поэтому клик поднимается по родителям до объекта
  с `game_role` (`gameRoot` в `src/sceneSetup.js`).
- **Стекло.** Объекты с `userData.click_through` (стеклянный шар, снежный шар, банка со свечой)
  пропускают клик к тому, что внутри.
- **Свет.** Экспорт в режиме «Unitless» (COMPAT): яркость ламп в единицах Blender. Режим «Standard»
  переводит ватты в канделы (×683), и в Three.js сцена получается белой.
  Area-свет glTF не поддерживает: `Light_Fill` пересобирается как `RectAreaLight` из его extras
  (яркость дополнительно делится на π — подобрано сравнением с рендером Blender). Цвет мира Blender
  превращается в `AmbientLight`.
- **Тени.** Флаги из Blender: у ламп `cast_shadow` = Shadow в настройках лампы, у объектов `cast_shadow: false`,
  если в Object › Visibility выключена Shadow (так сделано у пламени). Камера теней точечных ламп — от 0.05 до 15 м:
  со значениями по умолчанию (0.5–500 м) огонь не отбрасывает теней.
- **Анимации.** В `userData.anim` лежат подсказки: `flicker`, `swing`, `sway`, `follow_track`.

## Гибридный режим (эксперимент): `?mode=hybrid`

Под прозрачным canvas лежит рисунок пустой комнаты 16:9 (`export/bg_room_wide.jpg`, 1917×1080 — для экранов 1366×768 и 1920×1080), в 3D только интерактивные
объекты (`export/hybrid.glb`, экспорт из `finder_hybrid.blend` через `export_glb(path=".../export/hybrid.glb")` —
путь указывать обязательно, иначе перезапишется `finder_room.glb`). Камера та же, поэтому 3D-объекты встают туда,
куда их «ждёт» рисунок.

В GLB есть невидимые заместители нарисованной мебели (свойство `hybrid_role` в Blender):
- `occluder` — только глубина (ёлка, скатерть, рамка камина, боковины шкафа): прячет 3D за нарисованным;
- `shadow_catcher` — `ShadowMaterial` (пол, ковёр, стены, полки, каминная полка): видны только тени на рисунке.

У ловцов теней есть невидимый «двойник» глубины, поэтому нарисованные поверхности перекрывают 3D (кромка полки закрывает дно кораблика).
Контактная тень под фигуркой — маленькая запечённая плашка (`*_ContactShadow`, клики проходят сквозь неё).
Параметры: `&shadowA=0.25` — плотность 3D-теней на рисунке, `&shadowSoft=12` — мягкость (радиус PCF); `&debug` — клавиша R накладывает `renders/hybrid_composite_wide.png`.
Обычный режим (полное 3D) открывается без `?mode=`.

### Анимация при находке
Если у цели есть свойство `anim_on_found` (например `"Salute"`), по клику проигрывается одноимённое действие (action)
из Blender один раз и фигурка остаётся в последней позе (`LoopOnce` + `clampWhenFinished`), без подсветки. Экспорт с анимацией: `export_glb(path=".../export/hybrid.glb", animations=True)`.
Цели без анимации по-прежнему подсвечиваются и «подпрыгивают» (увеличение).

## Размер кадра в окне браузера (`src/frameLayout.js`)
Окно браузера почти никогда не 16:9 (адресная строка, вкладки, панель задач), поэтому кадр не вписывается «с полями», а
увеличивается до заполнения окна, но обрезается не больше чем на `?crop=0.1` (10 % по каждой оси, поровну с двух сторон),
чтобы спрятанные у краёв цели не пропадали. Оставшиеся поля заполняются размытой затемнённой копией рисунка, а не чёрным.
3D-камера получает ту же обрезку через `setViewOffset` (`blenderCamera.js`), так что рисунок и 3D не расходятся.
Кнопка ⛶ в правом нижнем углу или клавиша F — полноэкранный режим: на мониторе 16:9 кадр встаёт ровно, без обрезки и полей.
Цели лучше держать во внутренних 90 % кадра — эта зона видна при любом окне.

### Свет от предметов (свеча слона №1)
Точечный свет из Blender со свойством `flicker` и плоскость-ореол со свойством `glow` (цвет `glow_color`, радиус `glow_radius`,
яркость `glow_opacity`) превращаются в вебе в мерцающий свет и аддитивный спрайт, который всегда смотрит в камеру
и мягко подсвечивает рисунок вокруг (`makeGlowSprite` в `sceneSetup.js`, мерцание — в кадровом цикле `FinderScene.jsx`).

### Стекло и живое пламя (свеча в стакане на столе)
Объект со свойством `glass` получает в вебе тонкий прозрачный глянцевый материал с лёгким тёплым свечением изнутри,
объект со свойством `flame` (начало координат — на фитиле) непрерывно вытягивается, сужается и покачивается.
Оба мерцают синхронно со светом свечи (`flicker`).
